# Shell tab Implementation Plan (slices A and B)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Shell tab per connected session that runs the user's own `mongosh` against that connection from an editor, with Run (selection or all), Cancel, an output pane and Format, without the password reaching argv, the environment, logs or history.

**Architecture:** Core gets a pure invocation builder, an output scrubber and a streaming process runner (modelled on `tools/probe.rs`), exposed through two new runtime commands and three events. The UI gets a pure shell view-model, a pure formatter, a `Workspace::Shell` view (the same level as `Workspace::Compare`) and a reducer module. The UI resolves the `mongosh` executable with the existing tool settings and passes the path in the command; core owns secrets, the tunnel address and the read-only refusal.

**Tech Stack:** Rust 2024, egui/eframe 0.32.3, `egui_kittest`, tokio, the existing `curlybrace-core::tools` module.

**Spec:** `docs/superpowers/specs/2026-11-10-shell-tab-design.md`

This plan covers slices **A (core runner) and B (first usable tab, including Format)**. History (C), table/tree output (D) and completion (E) get their own plans once B ships, as the data-compare and index-miss work did.

## Global Constraints

- The password is never in argv, never in the child's environment, never in a log, never in history. On disk only in the last-resort file fallback (owner-only 0600 directory, deleted when the run ends). (spec: Goals, Anti-goals)
- Child environment is `env_clear()` plus an absolute-only `PATH` and `HOME`; no shell; `process_group(0)`; cancel kills the group. (spec: Runner; `tools/probe.rs`)
- Output scrubbing replaces the exact password with `••••`, across chunk boundaries; best-effort, not a security boundary. Output is never persisted. (spec: Output scrubbing)
- `ConnectionConfig.read_only` connections are refused in **core** through `Command::is_write()`; production connections need the existing confirmation on every run. (spec: Read-only, Production)
- One run at a time per session; a disconnect or closing the app kills the process group. (spec)
- Format is a pure function with 2-space indents; a selection's starting depth comes from the text before it. (spec)
- Every user-visible string is a key in `crates/ui/locales/en.json` (nested). Report new keys at the end. (user rules: no hardcoded strings)
- Immutable updates in view-models; files under 400 lines typical, 800 max; tests in `<module>_tests.rs` files beside the module.
- Unit tests use a fake `mongosh` script in a temp dir; nothing in `.github/workflows` may use a database or `mongosh` (`scripts/check-no-db-in-ci.sh`).
- Conventional commits, subject lowercase, imperative; end with the attribution trailers from the session.

## Review Focus

1. Passwords with `@ : / % ? # " ' \`, spaces, and a newline: the connect line must still connect to the intended user and host, and must not be injectable as script. Test in Task 3.
2. The password split across two output chunks, and across stdout/stderr: must still be scrubbed. Test in Task 2.
3. A `mongosh` that exits without reading stdin, or a closed stdin pipe: no hang, no panic, a finished event with the exit status. Test in Task 4.
4. Cancel while the child has started grandchildren, and Cancel after the child already exited: the whole group dies, a second Cancel is harmless. Test in Task 4.
5. A script error: `mongosh` prints `Uncaught` on stdout and still exits 0, so the run must not look successful (Task 4 `ScriptErrors`); a failed connect must not run the script at all. Test in Task 4.
5b. Output that is not UTF-8, has no newline for megabytes, or exceeds the cap: lossy-decoded, chunked, the run cancelled at the cap with a "cap reached" outcome. Test in Task 4.
6. Run on an empty or whitespace-only script, or on a session that has disconnected: no process is started, and a clear message is shown. Tests in Tasks 5 and 8.

### Task 4: Streaming process runner

**Files:**
- Create: `crates/core/src/shell/run.rs`, `crates/core/src/shell/run_tests.rs`, `crates/core/src/shell/fake.rs` (test-only helper that writes a fake `mongosh` shell script into a temp dir)

**Interfaces:**
- Behaviour pinned by the spike (stdin is a REPL): the runner (1) writes `inv.preamble`, reads until the `__CB_READY__` / `__CB_FAILED__ <message>` sentinel and shows nothing before it; on `__CB_FAILED__` it shows the (scrubbed) message on `Stream::Stderr`, kills the group and finishes with `ConnectFailed` without ever writing the script; (2) then writes `inv.script`, closes stdin (EOF makes `mongosh` exit 0); (3) strips the prompt (`^[A-Za-z0-9_.-]*> ` at the start of a line, and a bare trailing `> `) and any `\r` from output; (4) routes lines beginning `Uncaught` (the error block until the next prompt) to `Stream::Stderr`, everything else to `Stream::Stdout`; (5) because mongosh exits 0 even after errors, the outcome is `ScriptErrors` when exit status is 0 and any `Uncaught` was seen, else `Exited(code)`.
- Consumes: `Invocation` (Task 3), `Scrubber` (Task 2), `kill_group` approach from `crates/core/src/tools/probe.rs:116`.
- Produces:
  ```rust
  pub enum Stream { Stdout, Stderr }
  pub enum Outcome { Exited(i32), ScriptErrors, ConnectFailed, Signalled, Cancelled, CapReached, StartFailed }
  pub struct ShellHandle { /* cancel flag + pid */ }
  impl ShellHandle { pub fn cancel(&self); }
  pub struct RunLimits { pub max_output_bytes: usize, pub chunk_bytes: usize }
  pub fn spawn_shell(exe: &Path, inv: Invocation, secrets: Vec<String>,
                     path_var: Option<&OsStr>, limits: RunLimits,
                     on_output: impl Fn(Stream, String) + Send + 'static,
                     on_done: impl FnOnce(Outcome) + Send + 'static)
                     -> ShellHandle;   // a failed spawn is reported as on_done(Outcome::StartFailed)
  ```
  Fake `mongosh` (`fake.rs`, `#[cfg(test)] pub(crate)`) is a shell script that mimics the REPL: it prints `> ` prompts, answers the sentinel line, echoes bare lines, prints `Uncaught \r...` for lines starting with `throw`, and exits 0 on EOF. Defaults: `max_output_bytes = 8 MiB`, `chunk_bytes = 8 KiB` (builder's call, constants in `run.rs`).

- [ ] **Step 1: Write failing tests** with the fake script: `streams_stdout_and_stderr_in_order_per_stream`, `reports_exit_status`, `password_not_in_args_or_env_seen_by_the_child` (the fake echoes its argv and `env`; argv equals `[--nodb, --quiet]`), `prompts_are_stripped_from_output`, `uncaught_blocks_go_to_stderr_and_give_script_errors`, `connect_failure_shows_a_scrubbed_message_kills_the_child_and_never_writes_the_script`, `script_is_written_only_after_the_ready_sentinel`, `incomplete_block_at_eof_ends_the_run_and_does_not_hang` (stdin is closed after the script, so an unfinished `1+` cannot wait for more input), `password_and_its_percent_encoded_form_in_output_are_masked`, `cancel_kills_the_whole_group` (fake starts a background `sleep`; assert it is gone), `second_cancel_and_cancel_after_exit_are_harmless`, `child_that_never_reads_stdin_does_not_hang`, `output_over_the_cap_cancels_with_cap_reached`, `non_utf8_output_is_decoded_lossily`, `long_line_without_newline_is_chunked`, `missing_executable_reports_start_failed`.
- [ ] **Step 2:** Run `cargo test -p curlybrace-core shell::run` — expect FAIL.
- [ ] **Step 3:** Implement with `std::process::Command` (no shell, `env_clear()`, `PATH` from absolute entries only, `HOME`, `process_group(0)`), one writer thread for stdin that tolerates a broken pipe, one reader thread per stream feeding a `Scrubber` each, and a waiter thread that calls `on_done` once.
