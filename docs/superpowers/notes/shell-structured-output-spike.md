# Shell tab: structured (EJSON) output spike (slice D)

Date: 2026-11-11. Tool: `mongosh` 2.14.1 (`/opt/homebrew/bin/mongosh`, macOS). Server: a throwaway
`/opt/homebrew/bin/mongod` on 127.0.0.1:27995, no auth, temp dbpath (stopped and deleted afterwards).
`mongosh` ran with a temporary `HOME`, so no config, log or history reached the real home. No other
MongoDB was touched. Seed: `spike.mixed` (2 docs: ObjectId, ISODate, Long, Decimal128, Int32, double,
UUID, BinData, Timestamp, regex, 7-level nesting, nested arrays, null, a 300-char string, a 150-element
array, a `pw` field), `spike.wide` (1 doc, 30 fields), `spike.many` (300 `{n, s}` docs), `spike.big`
(6 docs with a 1 MiB string each), `spike.scratch` (writes).

Harness: a Python driver that does what `run.rs` does: `mongosh --nodb --quiet`, the shipped preamble
(fixed prompt `\u0001CBP> `, `try { db = connect(...); print("__CB_READY__") } ...`), the script as one
`{ ... }` block written a line at a time paced by the `| ` continuation prompts, then (new) one or
more epilogue lines after the prompt came back, one line per prompt. Raw output is quoted below with the
prompt shown as `<P>` and U+0001 as `<SOH>`.

## Recommendation

**Use the REPL's `_` (last value) in a one-line epilogue, sent after the block evaluated, calling an
emitter function that the preamble defined. For a cursor, read the batch the echo already printed from
`_._currentIterationResult` (no extra server round trip).**

Preamble addition (one statement, put on the existing preamble line before the `try { db = connect` part;
it holds no secret and no token):

```js
__cbEmit = ((P, E, SYM) => (v, T, MAXN, MAXB) => { const out = o => P(T + E.stringify(o, null, 0, {relaxed: false})); try { const t = v !== null && typeof v === "object" ? v[SYM] : undefined; const r = t !== undefined && v._currentIterationResult; let o; if (r && Array.isArray(r.documents)) { o = {k: "cursor", t: String(t), more: !!r.cursorHasMore, v: r.documents.slice(0, MAXN)} } else if (Array.isArray(v)) { o = {k: "array", n: v.length, more: v.length > MAXN, v: v.slice(0, MAXN)} } else if (v !== null && typeof v === "object") { o = {k: "object", t: t === undefined ? null : String(t), v: v} } else { o = {k: "scalar", v: v === undefined ? null : v, u: v === undefined} } const s = E.stringify(o, null, 0, {relaxed: false}); if (s.length > MAXB) { out({k: "too_big", bytes: s.length}) } else { P(T + s) } } catch (e) { out({k: "unsupported", t: v && v.constructor ? String(v.constructor.name) : null}) } })(print, EJSON, Symbol.for("@@mongosh.shellApiType"));
```

Epilogue (one line, written only after `Piece::Evaluated` of a complete block with no `Uncaught`;
`<TOKEN>` is a fresh random per-run token, e.g. 16 hex chars from the OS RNG, generated by the app and
sent ONLY here, never in the preamble):

```js
__cbEmit(_, "\u0001CBJ-<TOKEN> ", 200, 4194304)
```

Output of the epilogue: exactly one line `\u0001CBJ-<TOKEN> <canonical EJSON>\n`, then an empty line
(`print` returns `undefined`), then `<P>`. Then close stdin, as today after the prompt.

Payload shapes (canonical EJSON, `relaxed: false`, so the app's `bson` crate can parse every type):

| `k` | Fields | When | UI |
| --- | --- | --- | --- |
| `cursor` | `t` (`Cursor`, `AggregationCursor`, ...), `more` (bool), `v` (array of docs) | last value is a cursor that the echo iterated | table/tree of `v`; `more: true` -> "first N documents shown (more in cursor)" |
| `array` | `n` (total length), `more` (`n > 200`), `v` (first 200 elements) | `toArray()`, array literal, `getCollectionNames()` | table only when every element of `v` is a document; otherwise tree or "no table" |
| `object` | `t` (`Document`, `InsertOneResult`, `UpdateResult`, `ExplainOutput`, ... or `null` for a plain object), `v` | `findOne()`, `runCommand()`, write results, explain, object literal | tree (or a one-row table) |
| `scalar` | `v`, `u` (true when `undefined`) | number, string, bool, null, `undefined` | no table: "the result is not documents" |
| `too_big` | `bytes` | EJSON of the payload > 4 MiB | no table: "result too large for the table view (N MB)" |
| `unsupported` | `t` (constructor name) | `db`, `db.coll`, an object holding a cursor (circular) | no table: "the result cannot be shown as documents" |
| (no line) | | epilogue not sent (error, incomplete, early end) or the line did not arrive | no table, no message beyond the existing outcome |

Biggest caveat: `_currentIterationResult` (and the `@@mongosh.shellApiType` symbol) are mongosh
internals, not a documented API. They are present in 2.14.1; a later mongosh could rename them. The
emitter then falls into the `object` branch, `EJSON.stringify` hits the cursor's circular `_mongo`
reference and the result is `unsupported` (verified: that is what a cursor without the field gives),
so the failure mode is "no table", not wrong data. The gated real-mongosh test should assert the
`cursor` shape so that an upgrade that breaks it is noticed.

## Q1: is `_` usable after the block?

Yes. `_` is the completion value of the whole `{ ... }` block (the same value the REPL echoed).
Important: `_` is updated by EVERY evaluated line, so the probe must read it in the first epilogue
line (a second line sees the `undefined` of the first `print`):

```
epilogue line 1: print("\u0001CBJ typeof=" + typeof _ + " ctor=" + ...)   -> <SOH>CBJ typeof=object ctor=Array
epilogue line 2: print("\u0001CBJ " + EJSON.stringify(_, ...))           -> <SOH>CBJ null
```

Cursor details (from a probe of `_` after `db.many.find({}, {_id: 0})`): `_` is the `Cursor` itself,
already advanced by the echo: `objsLeftInBatch()` = 81 (first batch 101, 20 consumed), `hasNext()` =
true. `EJSON.stringify(_)` fails: `Converting circular structure to EJSON: (root) -> _mongo ->
_databases -> spike -> _mongo`. `toArray()`/`it`/`next()` on it would return docs 21+, not the echoed
20 (`it` inside the block is a plain function anyway, see the stdin spike). The cursor's own keys are
`_mongo,_transform,_blockingWarningDisabled,_cursor,_constructionOptions,_chains,_currentIterationResult,_tailable`;
`_currentIterationResult` is a `CursorIterationResult` with `documents` (exactly the echoed docs) and
`cursorHasMore` (true when `Type "it" for more` was printed). Same for `AggregationCursor`. The cursor
classes are not globals (`typeof Cursor` is `undefined`); `require`, `process`, `EJSON`, `config` are.

## Q3: interaction with the runner

(i) **Pacing / `Outcome::Incomplete`.** The epilogue is a single complete statement, so `mongosh`
prints no `| ` for it: the sequence is `... <P>` (Evaluated) -> write the epilogue -> `<SOH>CBJ-<TOKEN> {...}\n\n<P>`.
Send it only when the block is fully evaluated: Evaluated seen, all lines asked for, not `incomplete`,
no `Uncaught` seen. In every other case (syntax error part way, stray `}`, open bracket, error) do not
send it and close stdin exactly as today (the stdin spike showed that anything written after an early
evaluation is run as code; that rule is unchanged). The classifier needs one new phase after Evaluated:
expect one more `PROMPT`; the line that starts (at line start) with `\u0001CBJ-<TOKEN> ` is the payload,
the single empty line after it is dropped, everything else in that window is ordinary output (see the
async case below). After that prompt the run ends as today. If the script redefined `prompt`, Evaluated
is never seen (existing limitation), so the epilogue is never sent: no table.
*Superseded: both are now locked in the preamble (see Task 2 fix round); redefinition attempts
are ignored or error; the remaining known stall is a script that silences `process.stdout.write`,
ended only by Cancel.*

(ii) **Multi-batch cursors / caps.** The recommended emitter sends what the echo printed: at most
`displayBatchSize` docs (20 by default, `config.get("displayBatchSize")` = 20 here; a user's mongosh
config could change it, the epilogue just follows it) and `more = cursorHasMore`. Zero extra server
operations (profiler, below). Caps: `MAXN = 200` elements (arrays; cursors never exceed the echo batch),
`MAXB = 4 MiB` (4194304 chars of EJSON, measured as JS string length; the app should also enforce a
byte cap when reading the line, e.g. drop a payload line > 8 MiB). `hasMore` comes from
`cursorHasMore` (cursor) or `n > 200` (array).
Tested alternative (NOT recommended for v1): continue the cursor in the epilogue up to 200 docs
(`while (docs.length < MAXN && v.hasNext()) docs.push(v.next())`, skipped for `_tailable`). It works
(`cursor`, `n: 200`, `more: true`) but adds reads: one `getMore` that fetched 199 docs for the default
batch, or 36 `getMore`s with `batchSize(5)`; epilogue 321-596 ms vs ~15 ms; the table would show more
than the text pane; a tailable/change-stream cursor could block in `hasNext()` (guess, not tested: no
replica set). If wanted later, gate it on `t` in {Cursor, AggregationCursor} and not `_tailable`.

(iii) **Large results.** `print` writes the payload as one line, no wrapping: a 3,145,895-byte line
arrived intact through the pipe; 6.3 MB was refused by the emitter (`too_big`). The epilogue line
itself is ~50 bytes (the emitter lives in the preamble), so stdin line length is not an issue. The text
echo itself is not truncated for 1 MiB strings in documents from the server (1,048,588-char lines), so
the text pane already handles multi-MB lines; the existing output byte cap in `run.rs` must count the
side-channel line separately (or a 4 MiB payload would eat the text budget). Guess: no mongosh line
limit applies to stdout; none observed up to 3 MB.

(iv) **Errors.** On `throw`, `_` is not updated (it kept the preamble's `undefined`), so even a
mistakenly sent epilogue gives `scalar/u:true`. Rule: no epilogue after `Uncaught`. Any exception
inside the emitter (circular structure, a getter that throws) is caught and becomes `unsupported`; the
emitter never throws into the shell, so it never produces an `Uncaught` that the classifier would count
as a script error.

(v) **Password scrubbing.** The payload carries document data, so it must go through the same
`Scrubber` before parsing, and must never be shown in the text pane. Finding: the scrubber's secrets
are `[password, percent_encode(password)]` (`runtime/shell_handlers.rs:252`). A string is rendered
differently per channel: a stored `p"a'ss\w/é` shows in the text echo as `` `p"a'ss\\w/é` `` (backslash
doubled) and in EJSON as `"p\"a'ss\\w/é"`. So a password containing `\` (both channels) or `"`
(EJSON) or a control char is NOT masked by the current secret list. Add the JSON-escaped form (and the
JS-inspect-escaped form for the text pane) to the secret list. Masking inside the JSON keeps it valid
(MASK `••••` has no `"` or `\`, and the whole escaped form is replaced), but it changes field values,
so the table shows `••••` too (intended). Scrub first, then parse; a payload that fails to parse after
scrubbing -> no table.

(vi) **Spoofing / user `_`.** The token is in the epilogue only, sent after the script finished, so
the script cannot know it: `print("\u0001CBJ-7f3a9c {\"k\":\"fake\"}")` with the token guessed shows
as normal output (`| | <SOH>CBJ-7f3a9c {"k":"fake"}`), and only lines after Evaluated are considered
anyway. Also: inside the payload all strings are JSON-escaped, so stored data cannot start a new line.
Async output can arrive in the epilogue window or after it: `setTimeout(() => print("late-print"), 50)`
printed `late-print` after the epilogue's prompt; treat non-payload lines in that window as text. A
script that overrides `print = () => {}` and `EJSON = null` still gets its table (the emitter captured
both at preamble time: `{"k":"array",...,"v":[{"a":{"$numberInt":"1"}}]}`). A script that assigns
`__cbEmit` breaks the table (the line is missing or wrong; its own data only). A script that assigns
`_` disables the REPL's `_` for the session (`Expression assignment to _ now disabled.` is printed in
the text) and the table shows the user's value. Mitigation: if that exact text appears in the block's
output, skip the epilogue (spoofable only by the user's own script, harmless).

(vii) **Read-only / production.** The emitter only reads JS values already in memory. Profiler
(level 2 on `spike`) for `find`, `db.many`, `db`, `({c: db.many.find(..)})`, `$out` aggregate and
`batchSize(5)`, with and without the epilogue: the operation lists are identical (`find` nret=101;
`aggregate` once; `find` + 3 `getMore`; the trailing `killCursors` at exit). The lazy cursor inside an
object was never executed (no `find` for `{n: 1}` in either run). `_` of a write (`insertOne`,
`updateMany`) is just the result object. `EJSON.stringify` does call `toJSON` on objects it meets;
the shell API objects tested (Cursor, Collection, Database) failed with the circular error before
anything ran, but a user object with a side-effecting `toJSON` would run it (the user's own code). No
change to the read-only/production gating is needed: the epilogue is not a script and issues no
commands.

Also: the epilogue line is logged by mongosh as `Evaluating input` in the user's mongosh log (stdin
spike finding); it contains the token only.

## Q4: cost

Medians of 7 runs on a busy machine (handshake was ~2 s throughout, vs 0.55 s on a quiet one):

| Case | Epilogue | Epilogue time | Payload bytes |
| --- | --- | --- | --- |
| `42` | short (emitter in preamble) | 21 ms (10-51) | 68 |
| `db.many.find()` (20 docs) | short | 17 ms (10-66) | 805 |
| `db.many.find()` (20 docs) | whole emitter inline in the epilogue | 62 ms (35-159) | 805 |
| `find(...).toArray()` (200 docs) | short | 13 ms (10-34) | 7,857 |
| `find()` continued to 200 docs (not recommended) | inline | 445 ms (321-596) | 7,870 |
| 3 x 1 MiB docs | short | 489 ms | 3,145,899 |

Defining the emitter in the preamble did not change the handshake time measurably (1908 vs 2001 ms
medians, noise). The inline variant is slower because `mongosh` async-rewrites every input line
(parse cost grows with line length), which is why the emitter goes in the preamble.

## Cases it cannot handle (UI)

- Documents that were printed, not returned (`forEach(printjson)`, `print(x)`, a loop of `printjson`):
  `scalar/u:true` -> "no table: the script returned no value" (option (a) could add this later).
- Scalars, strings, arrays of non-documents (`getCollectionNames()`): "no table: the result is not
  documents" (an array of scalars could be a one-column table; product choice).
- `db`, a collection, objects holding cursors or other shell objects: `unsupported` -> "the result
  cannot be shown as documents".
- Errors, syntax errors, incomplete or early-ended blocks: no epilogue -> no table, existing outcome.
- Scripts that assign `_`, `__cbEmit` or redefine `prompt`: no or wrong table (see Q3 vi).
  *Superseded for `prompt` and `__cbEmit`: both are now locked in the preamble (see Task 2 fix
  round); redefinition attempts are ignored or error; the remaining known stall is a script that
  silences `process.stdout.write`, ended only by Cancel.*
- Cursor docs past the echo batch: table shows the same <= 20 docs as the text, with "more documents
  in the cursor" when `more` is true.
- Over 200 array elements: first 200 + "showing 200 of N".
- Payload over 4 MiB: `too_big` -> "result too large for the table view".
- Type fidelity: docs from the server are decoded by the driver into JS values, so a stored double
  with an integral value (`Double(2.0)`) comes out as `{"$numberInt":"2"}` (the text echo shows `2`
  too); Int32 vs integral double cannot be told apart. Long, Decimal128, dates, binary, UUID,
  Timestamp, regex and ObjectId keep their types.

## Open risks

- Private mongosh internals (`_currentIterationResult`, `CursorIterationResult.documents/cursorHasMore`,
  `Symbol.for("@@mongosh.shellApiType")`): stable in 2.14.1 only as far as tested; degrade to
  `unsupported` (no table). Cover with the gated real-mongosh test.
- `_` semantics depend on the Node REPL and mongosh's async rewriter; a mongosh that stops setting
  `_` for the block would give `scalar/u:true` -> no table.
- Scrubber coverage for JSON-escaped / inspect-escaped passwords (Q3 v) is a real gap today for the
  text pane as well, not only for the side channel.
- Guess: change streams / tailable cursors as the last value were not tested (no replica set); the
  recommended emitter does not call `hasNext()`, so it should not block, but the echo itself may.
- Output byte budget: a 4 MiB payload must not count against the text pane cap, and the app must cap
  the line it buffers.
